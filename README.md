# BlackWoolTD

검은 양털을 경로 데이터로 사용하는 Minecraft Java 26.1 계열 타워 디펜스 데이터팩입니다.

맵 제작자는 검은 양털 길, 맵 시작점, 코어, 스폰 지점, 방향 가이드를 월드에 저장합니다. 운영자는 웨이브를 시작하고, 플레이어는 상점 아이템으로 방어 유닛을 자유 배치합니다.

몹, 아군, 웨이브, 경제 수치는 `tools/spec/*` JSON을 원본으로 관리합니다. JSON을 바꾼 뒤에는 `uv run python tools/tdgen.py build`와 `/reload`를 실행해야 새 설정이 적용됩니다.

## 빠른 시작

```mcfunction
/reload
/function td:map/save_here
/function td:core/save_here
/function td:spawnpoint/save_here/1
/function td:path/guide/east
/function td:shop/give_items
/function td:wave/start
```

위 명령은 최소 흐름 예시입니다. 실제 맵에서는 시작점, 코어, 스폰 지점, 방향 가이드를 각각 알맞은 칸에서 실행해야 합니다.

## 지원 버전과 설치

- Minecraft Java Edition 26.1 계열
- 데이터팩 포맷: `101.1`
- 최신 데이터팩 구조인 `data/<namespace>/function` 및 `data/minecraft/tags/function` 단수 폴더를 사용합니다.

설치 위치:

```text
world/
  datapacks/
    BlackWoolTD/
      pack.mcmeta
      data/
      README.md
      .gitignore
```

### 도구 환경

타입과 웨이브 생성기는 `uv`로 실행합니다.

```bash
uv sync
uv run python tools/tdgen.py validate
uv run python tools/tdgen.py build
```

생성된 `.mcfunction` 파일 상단에 `Generated by tools/tdgen.py`가 있으면 직접 수정하지 않습니다. 수정은 `tools/spec`의 JSON에서 하고 다시 build합니다.

## 1. 맵 만들기

검은 양털(`minecraft:black_wool`)을 1칸 폭으로 깔아 적 이동 경로를 만듭니다. 적은 현재 칸의 동/서/남/북 검은 양털을 보고 이동하며, 방금 온 방향으로는 되돌아가지 않습니다. 갈림길이나 합류 지점에서 특정 다음 칸을 우선 선택하게 하려면 그 다음 칸의 바닥을 검은 콘크리트(`minecraft:black_concrete`)로 바꿀 수 있습니다.

| 해야 할 일 | 명령 |
| --- | --- |
| 시작점 저장 | `/function td:map/save_here` |
| 코어 저장 | `/function td:core/save_here` |
| 스폰 지점 저장 | `/function td:spawnpoint/save_here/1` ~ `/8` |
| 합류 지점 방향 가이드 | 다음 칸을 검은 콘크리트로 표시하거나 `/function td:path/guide/east`, `west`, `south`, `north` |
| 상태 확인 | `/function td:map/status`, `/function td:spawnpoint/status`, `/function td:core/status` |
| 게임 시작 | `/function td:wave/start` |

### 제작 순서

1. 검은 양털 시작 칸 위에 서서 시작점을 저장합니다.

```mcfunction
/function td:map/save_here
```

2. 지켜야 할 코어 블록 위에 서서 코어를 저장합니다.

```mcfunction
/function td:core/save_here
```

코어 marker는 활성 맵의 `td.map_id`에 묶입니다. 적이 이 marker 근처의 막다른 길에 도착하면 타입별 `td.core_damage`만큼 코어 HP가 줄어듭니다. 코어 에너지는 `td:core` bossbar로 표시됩니다.

3. 적이 나올 칸마다 서서 스폰 지점을 저장합니다.

```mcfunction
/function td:spawnpoint/save_here/1
/function td:spawnpoint/save_here/2
```

한 맵에는 스폰 지점 `1`부터 `8`까지 저장할 수 있습니다. 스폰 지점이 하나도 없으면 활성 맵 시작점인 `td.start`에서 적이 나옵니다.

4. 합류형 경로나 루프 위험이 있는 갈림길이 있다면 목적지로 이어지는 다음 칸을 검은 콘크리트로 바꿉니다. 기존 marker 방식이 필요하면 합류 칸에서 목적지 방향 가이드를 저장할 수도 있습니다.

```mcfunction
/function td:path/guide/east
/function td:path/guide/west
/function td:path/guide/south
/function td:path/guide/north
```

5. 저장 상태를 확인합니다.

```mcfunction
/function td:map/status
/function td:spawnpoint/status
/function td:core/status
```

6. 플레이어에게 상점 아이템을 지급하고 게임을 시작합니다.

```mcfunction
/function td:shop/give_items
/function td:wave/start
```

### 경로 규칙

- 검은 양털 경로는 평면 1칸 폭을 기준으로 합니다.
- 대각선 이동은 지원하지 않습니다.
- 시작점은 막다른 길로 만들고, 도착 지점에는 코어 marker를 저장합니다.
- 코어가 아닌 막다른 길에 적이 도착하면 경로 오류로 처리되며 코어 HP는 줄지 않습니다.
- 갈림길은 지원합니다. 후보가 여러 개면 적마다 랜덤으로 하나를 고릅니다.
- 두 길이 다시 만나는 합류 칸이나 루프 위험이 있는 갈림길에는 목적지로 이어지는 다음 칸을 검은 콘크리트로 표시하거나 목적지 방향 가이드를 둡니다.
- 검은 콘크리트는 랜덤 후보가 아니라 우선 진행 타일입니다. 나머지 일반 경로는 검은 양털로 유지합니다.
- 순환 경로는 방문 기록이 없으므로 피합니다.

### 여러 맵 운영

월드 안에 여러 시작점을 저장할 수 있지만, 게임은 항상 하나의 활성 맵만 사용합니다.

| 작업 | 명령 |
| --- | --- |
| 현재 위치를 새 맵 시작점으로 저장하고 활성화 | `/function td:map/save_here` |
| 8블록 안의 가장 가까운 저장 맵 활성화 | `/function td:map/activate_nearest` |
| 8블록 안의 가장 가까운 저장 맵 삭제 | `/function td:map/remove_nearest` |

맵을 활성화하면 기존 적, 방어 유닛, 웨이브 상태, 코어 HP가 초기화됩니다. 맵을 삭제하면 같은 `td.map_id`에 묶인 스폰 지점과 코어도 함께 삭제됩니다.

## 2. 웨이브 구성하기

웨이브는 JSON으로 관리하고 `.mcfunction`으로 생성합니다.

```text
tools/spec/waves/
  wave_01.json
  wave_02.json
  ...
  wave_20.json
```

각 JSON에는 “몇 tick에 무엇을 소환할지”와 “언제 스폰 완료로 볼지”만 적습니다. 웨이브 시작, 클리어, 준비 시간, 승리, 패배는 `td:wave/*`가 공통 처리합니다.

| 목적 | 예시 |
| --- | --- |
| 활성 스폰 지점 중 랜덤 | `execute if score $wave_time td.wave_time matches 20 run function td:spawn/random {type:"basic"}` |
| 특정 번호 스폰 지점 | `execute if score $wave_time td.wave_time matches 100 run function td:spawn/from {type:"fast",id:2}` |
| 모든 활성 스폰 지점 | `execute if score $wave_time td.wave_time matches 200 run function td:spawn/all {type:"tank"}` |
| 웨이브 스폰 완료 | `execute if score $wave_time td.wave_time matches 300 run scoreboard players set $wave_done td.wave_done 1` |

JSON 예시:

```json
{
  "number": 1,
  "title": "basic x3",
  "complete_tick": 140,
  "events": [
    {"tick": 20, "mode": "random", "type": "basic"},
    {"tick": 50, "mode": "random", "type": "basic"},
    {"tick": 80, "mode": "random", "type": "basic"}
  ]
}
```

생성되는 함수 예시:

```mcfunction
# Wave 01: basic x3
execute if score $wave_time td.wave_time matches 20 run function td:spawn/random {type:"basic"}
execute if score $wave_time td.wave_time matches 50 run function td:spawn/random {type:"basic"}
execute if score $wave_time td.wave_time matches 80 run function td:spawn/random {type:"basic"}
execute if score $wave_time td.wave_time matches 140 run scoreboard players set $wave_done td.wave_done 1
```

`$wave_done`이 `1`이고 남은 `td.enemy`가 없으면 웨이브가 클리어됩니다. 완료 tick은 마지막 적이 충분히 나올 시간을 둔 뒤로 잡는 것이 좋습니다.

## 3. 몹 추가/수정하기

현재 적 타입은 `basic`, `fast`, `tank`, `boss`입니다.

| 타입 | 랜덤 소환 예시 | 엔티티 | 기본 HP | 기본 속도 | 기본 보상 | 코어 피해 |
| --- | --- | --- | ---: | --- | ---: | ---: |
| basic | `td:spawn/random {type:"basic"}` | zombie | 10 | normal | 5 | 1 |
| fast | `td:spawn/random {type:"fast"}` | vindicator | 6 | fast | 6 | 1 |
| tank | `td:spawn/random {type:"tank"}` | pillager | 30 | slow | 15 | 3 |
| boss | `td:spawn/random {type:"boss"}` | evoker | 100 | slow | 80 | 10 |

### 기존 몹 수정

| 바꿀 것 | 수정 위치 |
| --- | --- |
| HP, 속도, 처치 보상, 코어 피해 | `tools/spec/enemies/<타입>.json` |
| 엔티티 종류 | `tools/spec/enemies/<타입>.json`의 `entity` |
| 장비, 크기, 소환 이펙트 | `tools/spec/enemies/<타입>.json`의 `equipment`, `scale`, `effects` |
| 머리 위 체력바 표시 이름 | `tools/spec/enemies/<타입>.json`의 `display_name`, `bold` |

속도 값은 `1 = slow`, `2 = normal`, `3 = fast`입니다.

### 새 몹 추가 체크리스트

새 타입 이름은 매크로의 `type` 값과 파일명이 같아야 합니다.

```bash
uv run python tools/tdgen.py add enemy slime --from basic
```

1. 생성된 `tools/spec/enemies/slime.json`을 수정합니다.
2. 웨이브 JSON에서 `{"type":"slime"}`처럼 새 타입을 참조합니다.
3. `uv run python tools/tdgen.py build`를 실행합니다.

몹을 잠시 제거하려면 archive로 이동합니다.

```bash
uv run python tools/tdgen.py delete enemy slime
uv run python tools/tdgen.py restore enemy slime
```

## 4. 아군 추가/수정하기

현재 방어 유닛은 `basic`, `splash`, `blink`입니다.

| 타입 | 명령 배치 | 기본 비용 | 피해 | 사거리 | 공격 주기 | 특징 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| basic | `/function td:tower/place {type:"basic"}` | 20 | 4 | 8 | 40틱 | 단일 대상 |
| splash | `/function td:tower/place {type:"splash"}` | 40 | 3 | 7 | 60틱 | 타겟 주변 2.5블록 광역 |
| blink | `/function td:tower/place {type:"blink"}` | 70 | 5 | 12 | 100틱 | 순간이동 후 주변 3블록 광역 |

플레이어 배치는 `/function td:shop/give_items`로 받은 `minecraft:carrot_on_a_stick` 아이템을 우클릭해서 진행합니다. 아이템은 `minecraft:custom_data`의 `{td:{tool:"tower",tower:"basic"}}` 같은 값으로 타입을 구분합니다.

### 기존 아군 수정

| 바꿀 것 | 수정 위치 |
| --- | --- |
| 비용 | `tools/spec/towers/<타입>.json`의 `cost` |
| 공격 피해, 초기 쿨타임 | `tools/spec/towers/<타입>.json`의 `damage`, `initial_cooldown` |
| 상점 아이템 이름/설명 | `tools/spec/towers/<타입>.json`의 `shop` |
| 장비, 크기, 배치 이펙트 | `tools/spec/towers/<타입>.json`의 `equipment`, `scale`, `effects` |
| 사거리, 실제 공격 주기 | `tools/spec/towers/<타입>.json`의 `range`, `cooldown` |
| 공격 방식과 이펙트 | `tools/spec/towers/<타입>.json`의 `attack` |

`single`, `splash`, `blink` 공격은 preset으로 생성됩니다. 특수 공격은 `attack.preset`을 `raw`로 두고 JSON에 mcfunction 줄 목록을 직접 넣습니다.

### 새 아군 추가 체크리스트

새 아군 타입 이름은 매크로의 `type` 값, custom data의 `tower` 값, 파일명이 같아야 합니다.

```bash
uv run python tools/tdgen.py add tower frost --from basic
```

1. 생성된 `tools/spec/towers/frost.json`을 수정합니다.
2. `attack.preset`을 `single`, `splash`, `blink`, `raw` 중 하나로 정합니다.
3. `uv run python tools/tdgen.py build`를 실행합니다.

생성기는 config, shop 아이템, 우클릭 판정, 배치 분기, mannequin 소환, 타입 설정, tick, attack, function tag JSON을 모두 갱신합니다.

```bash
uv run python tools/tdgen.py delete tower frost
uv run python tools/tdgen.py restore tower frost
```

단일 타겟은 `td.tower.target`, 광역 대상은 `td.tower.hit`, blink 복귀 지점은 `td.tower.origin` marker를 사용합니다. 공격이 끝난 뒤 임시 태그가 남지 않도록 `tower/attack/run/<타입>`에서 `td:tower/clear_temp`를 호출하는 구조를 유지합니다.

## 5. 경제 시스템 조정하기

돈은 플레이어별 `td.money`로 관리됩니다. 적이 죽으면 그 적의 보상만큼 모든 온라인 플레이어가 같은 돈을 받습니다.

| 바꿀 것 | 수정 위치 | 기본값 |
| --- | --- | ---: |
| 시작 돈 | `tools/spec/game.json`의 `start_money` | 60 |
| 타워 비용 | `tools/spec/towers/<타입>.json`의 `cost` | 타입별 |
| 전투 중 환불 비율 | `tools/spec/game.json`의 `combat_refund_divisor` | 2 |
| 적 처치 보상 | `tools/spec/enemies/<타입>.json`의 `reward` | 타입별 |
| 적 코어 피해 | `tools/spec/enemies/<타입>.json`의 `core_damage` | 타입별 |
| 코어 HP | `tools/spec/game.json`의 `core_hp` | 20 |
| 웨이브 준비 시간 | `tools/spec/game.json`의 `wave_prep_ticks` | 600 |

환불 규칙:

- 웨이브 진행 중(`$wave_state = 1`): 구매가를 `$combat_refund_divisor`로 나눈 값 환불
- 대기, 준비 시간, 승리, 패배 상태: 100% 환불
- 맵 전환, 새 게임 시작, `td:reset/towers`: 환불 없음

`$combat_refund_divisor`가 `2`이면 50%, `4`이면 25%입니다. 나눗셈 값이므로 `0`으로 두면 안 됩니다.

## 6. 운영 명령/참조

### 생성기 명령

| 명령 | 역할 |
| --- | --- |
| `uv run python tools/tdgen.py validate` | spec JSON 참조와 필수 값을 검사 |
| `uv run python tools/tdgen.py build` | spec JSON에서 데이터팩 함수와 tag JSON 재생성 |
| `uv run python tools/tdgen.py list all` | 활성/보관 중인 몹, 아군, 웨이브 목록 표시 |
| `uv run python tools/tdgen.py add enemy slime --from basic` | 기존 몹을 복사해 새 몹 spec 생성 |
| `uv run python tools/tdgen.py add tower frost --from basic` | 기존 아군을 복사해 새 아군 spec 생성 |
| `uv run python tools/tdgen.py add wave 21 --from 20` | 기존 웨이브를 복사해 새 웨이브 spec 생성 |
| `uv run python tools/tdgen.py delete enemy slime` | spec을 `tools/spec/archive`로 이동하고 재생성 |
| `uv run python tools/tdgen.py restore enemy slime` | archive의 spec을 복구하고 재생성 |

### 운영 명령

| 명령 | 역할 |
| --- | --- |
| `/function td:shop/give_items` | 타워 배치 아이템과 제거 도구 지급 |
| `/function td:economy/status` | 실행 플레이어의 돈 확인 |
| `/function td:core/status` | 활성 코어와 코어 HP 확인 |
| `/function td:wave/status` | 웨이브, 코어 HP, 상태값, 준비 시간 확인 |
| `/function td:wave/next` | 준비 시간 중 다음 웨이브로 즉시 진행 |
| `/function td:wave/stop` | 웨이브 중지와 남은 적 정리 |
| `/function td:reset/enemies` | 적만 정리 |
| `/function td:reset/towers` | 방어 유닛만 정리 |
| `/function td:reset/all` | 적과 방어 유닛 모두 정리 |

`td:wave/start`는 새 게임 시작용입니다. 적과 방어 유닛을 모두 정리하고, 코어 HP와 플레이어 돈을 config 값으로 되돌린 뒤 1웨이브를 시작합니다.

### 주요 공개 함수

| 함수 | 역할 |
| --- | --- |
| `td:map/save_here` | 현재 위치에 맵 시작점을 저장하고 활성화 |
| `td:map/activate_nearest` | 8블록 안의 가장 가까운 저장 맵 활성화 |
| `td:map/remove_nearest` | 8블록 안의 가장 가까운 저장 맵 삭제 |
| `td:map/status` | 활성 맵과 현재 웨이브/코어 상태 표시 |
| `td:core/save_here` | 발밑 블록을 활성 맵 코어로 저장 |
| `td:core/remove_nearest` | 가까운 활성 맵 코어 삭제 |
| `td:core/status` | 활성 맵 코어와 코어 HP 표시 |
| `td:spawnpoint/save_here/1` ~ `/8` | 활성 맵에 번호별 스폰 지점 저장 |
| `td:spawnpoint/remove_nearest` | 가까운 활성 스폰 지점 삭제 |
| `td:spawnpoint/status` | 활성 맵의 스폰 지점 상태 표시 |
| `td:path/guide/east`, `west`, `south`, `north` | 현재 칸에 marker 기반 강제 진행 방향 저장 |
| `td:path/guide/remove_nearest` | 가까운 방향 가이드 삭제 |
| `td:spawn/random {type:"basic"}` | 활성 스폰 지점 중 랜덤 위치에 적 소환 |
| `td:spawn/from {type:"fast",id:2}` | 해당 번호 스폰 지점에서 적 소환 |
| `td:spawn/all {type:"tank"}` | 모든 활성 스폰 지점에서 적 소환 |
| `td:tower/place {type:"basic"}` | 명령으로 현재 위치에 타워 구매 배치 |
| `td:tower/remove_nearest` | 가까운 본인 소유 타워 환불 제거 |
| `td:wave/start` | 새 게임 시작 |

### 확장용 function tag

아래 tag JSON은 생성기가 관리합니다. 타입을 추가할 때 직접 수정하지 말고 `tools/spec`를 수정한 뒤 build합니다.

| Tag | 용도 |
| --- | --- |
| `#td:config/load` | 새 설정 함수 등록 |
| `#td:shop/give_items` | 상점 지급 아이템 등록 |
| `#td:shop/use_items` | 우클릭 아이템 판정 등록 |
| `#td:tower/place_types` | 선택된 아군 타입의 실제 배치 분기 등록 |
| `#td:tower/tick_types` | 타입별 아군 tick 처리 등록 |
| `#td:enemy/hpbar_types` | 타입별 적 체력바 갱신 등록 |

### 중요한 점수판

| Objective | 용도 |
| --- | --- |
| `td.hp` | 코어 HP와 일부 HP 관련 fake player |
| `td.enemy_hp`, `td.enemy_max_hp` | 적 현재/최대 HP |
| `td.core_damage` | 적이 코어에 도착했을 때 줄 피해량 |
| `td.reward` | 적 처치 보상 |
| `td.money` | 플레이어 개인 돈 |
| `td.place_cost` | 배치 비용과 비용 config fake player |
| `td.tower_cost` | 배치된 타워의 구매가 |
| `td.tower_cd` | 타워 공격 쿨타임 |
| `td.wave`, `td.wave_time`, `td.wave_state`, `td.wave_done`, `td.wave_prep` | 웨이브 진행 상태 |
| `td.map_id`, `td.spawn_id` | 맵과 스폰 지점 연결 |
| `td.dir`, `td.next`, `td.branch_count`, `td.branch_pick`, `td.path_dir` | 검은 양털 경로 이동과 분기/가이드 |
| `td.tmp` | 공통 임시 계산과 일부 config fake player |

`.mcfunction` 파일은 `#` 주석을 사용할 수 있습니다. `pack.mcmeta`, `load.json`, `tick.json`은 JSON이므로 주석을 넣지 않습니다.
