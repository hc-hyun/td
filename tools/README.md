# BlackWoolTD Node.js Tools

이 문서는 `tools/tdgen.js` 사용법만 다룹니다. 맵 제작, 스폰 지점, 코어, 웨이브 시작 같은 인게임 운영은 루트 `README.md`를 참고합니다.

`tdgen.js`는 `tools/spec/*.json`을 읽어서 데이터팩 함수와 function tag JSON을 다시 만드는 생성기입니다. 몹, 타워, 웨이브, 경제 수치를 바꿀 때는 생성된 `.mcfunction`을 직접 고치지 말고 spec JSON을 수정한 뒤 build합니다.

## Quickstart

처음에는 아래 순서만 기억하면 됩니다.

```bash
npm run tdgen -- validate
npm run tdgen -- build
```

그다음 Minecraft 안에서 데이터팩을 다시 불러옵니다.

```mcfunction
/reload
```

자주 쓰는 루틴은 이렇습니다.

1. `tools/spec` 안의 JSON을 수정합니다.
2. `npm run tdgen -- validate`로 실수를 확인합니다.
3. `npm run tdgen -- build`로 `.mcfunction`과 tag JSON을 재생성합니다.
4. 게임 안에서 `/reload`를 실행합니다.

## 핵심 개념

### 원본과 생성물

원본은 `tools/spec`입니다.

```text
tools/spec/
  game.json
  enemies/
  towers/
  waves/
  archive/
```

생성물은 주로 `data/td/function`과 `data/td/tags/function`에 만들어집니다. 파일 첫 줄이 아래 문구라면 생성기가 관리하는 파일입니다.

```text
# Generated by tools/tdgen.js. Do not edit directly.
```

이 파일들은 `build` 때 다시 쓰일 수 있으므로 직접 수정하지 않습니다.

### 활성 spec과 archive

`tools/spec/enemies`, `tools/spec/towers`, `tools/spec/waves`에 있는 JSON은 활성 상태입니다. `tools/spec/archive` 아래로 이동된 JSON은 보관 상태이며 build 대상에서 빠집니다.

`delete`와 `restore` 명령은 파일을 archive로 옮기거나 다시 활성 위치로 돌린 뒤 자동으로 build합니다.

## 명령어

### validate

spec JSON이 생성 가능한 상태인지 검사합니다.

```bash
npm run tdgen -- validate
```

검사하는 대표 항목:

- 필수 필드가 있는지
- 적/타워 id가 소문자, 숫자, 밑줄만 쓰는지
- 웨이브가 존재하지 않는 적 타입을 참조하지 않는지
- `from` 스폰 이벤트에 `id`가 있는지
- 전투 중 환불 divisor가 0보다 큰지
- archive와 활성 spec에 같은 id가 동시에 있지 않은지

### build

spec JSON을 기준으로 데이터팩 파일을 재생성합니다.

```bash
npm run tdgen -- build
```

`build`는 먼저 `validate`를 실행합니다. 통과하면 생성기가 관리하는 기존 파일을 정리하고, config, spawn, enemy, tower, wave, tag JSON을 다시 씁니다.

### list

활성/보관 중인 spec을 확인합니다.

```bash
npm run tdgen -- list all
npm run tdgen -- list enemy
npm run tdgen -- list tower
npm run tdgen -- list wave
```

출력 예시:

```text
[enemies]
  active   basic
  active   fast
  active   tank
  active   boss
```

### add

기존 spec을 복사해서 새 spec을 만들고 바로 build합니다.

```bash
npm run tdgen -- add enemy slime --from basic
npm run tdgen -- add tower frost --from basic
npm run tdgen -- add wave 21 --from 20
```

적/타워를 추가할 때 새 id는 소문자, 숫자, 밑줄만 사용합니다. 웨이브는 `21` 또는 `wave_21`처럼 지정할 수 있습니다.

복사 직후에는 기본값이 많이 남아 있으므로 생성된 JSON을 열어 이름, 수치, 장비, 이벤트를 조정합니다.

### delete

활성 spec을 archive로 옮기고 바로 build합니다.

```bash
npm run tdgen -- delete enemy slime
npm run tdgen -- delete tower frost
npm run tdgen -- delete wave 21
```

삭제라기보다 “비활성 보관”에 가깝습니다. JSON은 `tools/spec/archive/...` 아래에 남습니다.

### restore

archive의 spec을 다시 활성 위치로 옮기고 바로 build합니다.

```bash
npm run tdgen -- restore enemy slime
npm run tdgen -- restore tower frost
npm run tdgen -- restore wave 21
```

같은 id의 활성 spec이 이미 있으면 복구하지 않고 오류를 냅니다.

## 작업별 레시피

### 수치만 조정하기

예를 들어 basic 적의 HP와 보상을 바꾸려면:

1. `tools/spec/enemies/basic.json`을 엽니다.
2. `hp`, `reward`, `core_damage`, `speed` 등을 수정합니다.
3. `npm run tdgen -- validate`를 실행합니다.
4. `npm run tdgen -- build`를 실행합니다.
5. 게임 안에서 `/reload`를 실행합니다.

타워 비용과 공격력은 `tools/spec/towers/<id>.json`에서, 코어 HP와 시작 돈은 `tools/spec/game.json`에서 바꿉니다.

### 새 적 추가하기

```bash
npm run tdgen -- add enemy slime --from basic
```

생성된 `tools/spec/enemies/slime.json`에서 주로 바꿀 필드:

- `display_name`: 표시 이름
- `entity`: 소환할 엔티티 id
- `hp`, `speed`, `reward`, `core_damage`: 전투 수치
- `team.name`, `team.color`: 팀 이름과 색
- `scale`, `equipment`, `effects`: 외형과 등장 연출

수정 후:

```bash
npm run tdgen -- validate
npm run tdgen -- build
```

웨이브에서 새 적을 쓰려면 `tools/spec/waves/*.json` 이벤트의 `type`에 새 id를 넣습니다.

### 새 타워 추가하기

```bash
npm run tdgen -- add tower frost --from basic
```

생성된 `tools/spec/towers/frost.json`에서 주로 바꿀 필드:

- `display_name`: 표시 이름
- `cost`, `damage`, `range`, `cooldown`: 비용과 전투 수치
- `shop`: 상점 아이템 이름, 색, 설명, 반짝임
- `equipment`, `scale`, `effects`: 외형과 배치 연출
- `attack.preset`: 공격 방식

지원 preset:

| preset | 용도 |
| --- | --- |
| `single` | 가장 가까운 적 하나를 공격 |
| `splash` | 가장 가까운 적 주변 범위 공격 |
| `blink` | 적에게 순간이동해 범위 공격 후 복귀 |
| `raw` | 직접 작성한 mcfunction 줄을 사용 |

`splash`와 `blink`는 `attack.aoe`로 범위를 조정할 수 있습니다. `blink`는 `attack.blink_time`으로 복귀 전 대기 tick을 조정합니다.

### 새 웨이브 추가하기

```bash
npm run tdgen -- add wave 21 --from 20
```

생성된 `tools/spec/waves/wave_21.json`에서 바꿀 필드:

- `title`: 문서용 제목
- `complete_tick`: 스폰이 끝났다고 표시할 tick
- `events`: 몇 tick에 어떤 적을 어디서 소환할지

이벤트 예시:

```json
{"tick": 20, "mode": "random", "type": "basic"}
{"tick": 80, "mode": "from", "type": "fast", "id": 2}
{"tick": 160, "mode": "all", "type": "tank"}
```

`mode` 의미:

| mode | 결과 |
| --- | --- |
| `random` | 활성 스폰 지점 중 하나에서 소환 |
| `from` | 지정한 스폰 지점 번호에서 소환 |
| `all` | 모든 활성 스폰 지점에서 소환 |

`from`은 반드시 `id`가 필요합니다.

### 타입 보관/복구하기

잠시 빼고 싶은 적이나 타워는 `delete`로 archive에 보관합니다.

```bash
npm run tdgen -- delete enemy slime
```

다시 쓰려면 `restore`합니다.

```bash
npm run tdgen -- restore enemy slime
```

두 명령은 모두 자동으로 build하므로, 성공 후 게임 안에서는 `/reload`만 하면 됩니다.

## JSON 작성 가이드

### game.json

`tools/spec/game.json`은 전역 설정입니다.

```json
{
  "core_hp": 20,
  "wave_prep_ticks": 600,
  "hp_scale": 10,
  "start_money": 60,
  "combat_refund_divisor": 2
}
```

주요 필드:

| 필드 | 의미 |
| --- | --- |
| `core_hp` | 코어 기본 체력 |
| `wave_prep_ticks` | 웨이브 사이 준비 시간 |
| `hp_scale` | 체력바 비율 계산 기준 |
| `start_money` | 새 게임 시작 돈 |
| `combat_refund_divisor` | 전투 중 환불 divisor. `2`면 50% |
| `tower_team` | 타워 팀 이름, 색, 충돌 규칙 |

`combat_refund_divisor`는 1 이상이어야 합니다.

### enemies/*.json

적 spec의 기본 모양:

```json
{
  "id": "basic",
  "display_name": "Basic",
  "order": 10,
  "entity": "minecraft:zombie",
  "hp": 10,
  "speed": 2,
  "reward": 5,
  "core_damage": 1,
  "team": {
    "name": "td_enemy_basic",
    "color": "green",
    "collision_rule": "never"
  }
}
```

주요 필드:

| 필드 | 의미 |
| --- | --- |
| `id` | 타입 id. 파일명과 맞춥니다 |
| `display_name` | 이름표와 체력바에 쓰는 이름 |
| `order` | list/build 정렬용 값 |
| `entity` | 소환할 Minecraft 엔티티 id |
| `hp` | 최대 체력 |
| `speed` | `1 = slow`, `2 = normal`, `3 = fast` |
| `reward` | 처치 보상 |
| `core_damage` | 코어 도착 시 피해 |
| `team` | 팀 이름, 색, 충돌 규칙 |
| `scale` | 엔티티 크기 |
| `equipment` | 장비 목록 |
| `effects` | 타입 적용 시 실행할 mcfunction 줄 목록 |

### towers/*.json

타워 spec의 기본 모양:

```json
{
  "id": "basic",
  "display_name": "Basic",
  "cost": 20,
  "damage": 4,
  "initial_cooldown": 40,
  "range": 8,
  "cooldown": 40,
  "shop": {
    "item_name": "Basic Tower",
    "color": "green",
    "lore": "Configured cost | Single target"
  },
  "attack": {
    "preset": "single"
  }
}
```

주요 필드:

| 필드 | 의미 |
| --- | --- |
| `id` | 타워 id. 파일명, custom data, 함수 경로에 쓰입니다 |
| `cost` | 구매 비용 |
| `damage` | 공격 피해 |
| `initial_cooldown` | 배치 직후 첫 공격까지의 초기 쿨타임 |
| `range` | 공격 대상 탐색 거리 |
| `cooldown` | 공격 주기 tick |
| `shop` | 상점 아이템 표시 정보 |
| `mannequin` | 소환할 mannequin profile과 회전 |
| `equipment` | 들고 있거나 착용할 아이템 |
| `effects` | 배치 시 실행할 연출 줄 |
| `attack` | 공격 preset과 세부 옵션 |

### waves/*.json

웨이브 spec의 기본 모양:

```json
{
  "number": 1,
  "order": 1,
  "title": "basic x6",
  "complete_tick": 220,
  "events": [
    {"tick": 20, "mode": "random", "type": "basic"}
  ]
}
```

주요 필드:

| 필드 | 의미 |
| --- | --- |
| `number` | 웨이브 번호. 파일명 `wave_01.json`과 맞춥니다 |
| `order` | 정렬용 값 |
| `title` | 생성 함수 주석에 들어가는 제목 |
| `complete_tick` | 스폰 완료로 표시할 tick |
| `events` | 스폰 이벤트 목록 |

`complete_tick`은 마지막 스폰 이벤트보다 충분히 뒤로 잡는 것이 좋습니다.

## 고급 사용

### raw 공격 preset

특수 타워는 `attack.preset`을 `raw`로 두고 직접 mcfunction 줄을 넣을 수 있습니다.

```json
{
  "attack": {
    "preset": "raw",
    "tick_lines": [
      "execute as @e[type=minecraft:mannequin,tag=td.tower.frost] at @s run function td:tower/attack/run/frost"
    ],
    "lines": [
      "scoreboard players set @s td.tower_cd 0",
      "particle minecraft:snowflake ~ ~1 ~ 0.4 0.4 0.4 0.02 20 force"
    ]
  }
}
```

`tick_lines`가 있으면 기본 타겟 탐색 tick 함수를 대신합니다. `lines`는 `td:tower/attack/<id>`의 본문이 됩니다.

### id 규칙

적과 타워 id는 아래 문자만 사용합니다.

```text
a-z, 0-9, _
```

좋은 예:

```text
ice_mage
slime2
frost_tower
```

피할 예:

```text
IceMage
ice-mage
ice mage
```

### archive 충돌

같은 id가 활성 폴더와 archive 폴더에 동시에 있으면 validate가 실패합니다. 복구하려면 한쪽을 지우거나 이름을 바꿔야 합니다.

## 문제 해결

### `tdgen: Missing spec file: tools/spec/game.json`

`tools/spec/game.json`이 없거나 실행 위치가 잘못됐을 가능성이 큽니다. 데이터팩 루트, 즉 `package.json`이 있는 위치에서 실행합니다.

### `tdgen: Invalid enemy id 'IceMage'. Use lowercase letters, numbers, and underscores.`

id에 대문자, 하이픈, 공백 같은 문자가 들어갔습니다. `ice_mage`처럼 소문자와 밑줄로 바꿉니다.

### `tdgen: wave 3 event is missing required field(s): type`

웨이브 이벤트에 필수 필드가 없습니다. 각 이벤트에는 최소 `tick`과 `type`이 필요합니다.

### `tdgen: Wave 7 references missing enemy type: slime`

웨이브가 참조하는 적 타입이 활성 `tools/spec/enemies`에 없습니다. 적 spec을 추가하거나, archive에 있다면 restore합니다.

### `tdgen: Wave 4 from-spawn event needs id`

`mode`가 `from`인 이벤트에 스폰 지점 번호 `id`가 없습니다.

```json
{"tick": 80, "mode": "from", "type": "fast", "id": 2}
```

### `tdgen: combat_refund_divisor must be greater than 0.`

`tools/spec/game.json`의 `combat_refund_divisor`가 0 이하입니다. `2` 같은 양수로 바꿉니다.

### build 후 게임에 반영되지 않음

`build`는 파일만 갱신합니다. 게임 안에서 `/reload`를 실행해야 데이터팩이 새 파일을 읽습니다.
